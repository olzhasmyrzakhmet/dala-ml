# CLAUDE.md — «Дала ML» (Kazakh-language ML learning platform)

Ты — ведущий инженер и дизайнер этого проекта. Цель: **работающая, красивая, быстрая платформа
на проде**, где сельский школьник с Android-телефона учится ML на казахском через интерактивные
степные метафоры.

## Документы (читать в этом порядке)
1. CLAUDE.md → 2. docs/PRD.md (продукт, моат, курс) → 3. docs/SPEC.md (техника до запятых)
→ 4. docs/PLAN.md (единственный источник задач).

## ПРОТОКОЛ РАБОТЫ
Пока в PLAN.md есть `- [ ]`: бери ПЕРВУЮ незакрытую задачу самой ранней фазы → сверься со SPEC
→ реализуй → прогони «Проверка:» → отметь `[x]` → commit. В конце каждой фазы:
`npm run build` + `npm run test` зелёные → **вызови субагента critic** → исправь CRITICAL/MAJOR
→ повторный критик (максимум 3 цикла) → деплой → `npm run prod:verify` → сырой вывод в отчёт.
Не спрашивай разрешения на шаги из плана. Блокер → обход + запись в TODO.md → дальше.

## ЖЁСТКИЕ ПРАВИЛА (нарушение = провал)
1. **Правда только на проде.** «Работает локально» ничего не значит. Каждый отчёт — с сырым
   выводом prod-verify с реального URL.
2. **Один хостинг-проект, домен зафиксирован в фазе 0** и захардкожен в prod-verify. Никогда не
   проверяй один адрес, деплоя в другой.
3. **Mobile-first буквально.** Верстаешь сначала под 360px, потом расширяешь. Любая страница с
   горизонтальным скроллом на 360px = CRITICAL.
4. **Бюджет производительности.** Первая загрузка < 200 КБ JS (без Pyodide), первый экран < 2с
   на 3G. Превысил — режь, а не оправдывайся. Pyodide грузится ТОЛЬКО по явному клику.
5. **Ни одного «ИИ-шного» экрана.** Запрещено: hero + три карточки с иконками, стоковые фото,
   градиентные кнопки, эмодзи в заголовках. Дизайн — через скилл ui-ux-pro-max/frontend-design
   ДО вёрстки, с артефактом DESIGN.md. Компоненты из 21st.dev MCP — можно, если вписываются.
6. **Казахский текст — священен.** Проверяй ВСЕ специфические глифы (ә ғ қ ң ө ұ ү һ і) в каждом
   выбранном шрифте. Ни одного «квадратика» или подмены глифа. Ни одной строки машинного
   перевода: если не уверен в формулировке — оставь TODO и спроси меня, не выдумывай.
7. **Каждый интерактив работает пальцем.** Ползунки, перетаскивание, тапы — тестируй тач-события,
   не только мышь. 44×44px минимальная зона нажатия.
8. **Офлайн реально работает.** Не «есть service worker», а: открыл модуль, выключил сеть,
   перезагрузил страницу — урок и интерактив живые. Это проверка, а не декларация.
9. **Никаких пустых состояний на витрине.** Прогресс, счётчики, примеры — всегда с осмысленным
   содержимым, даже у нового пользователя.
10. **Не ломать работающее.** После каждой фазы prod-verify полностью зелёный, включая прежние
    проверки. Регресс = CRITICAL.
11. **Контент важнее фич.** Лучше 3 идеально сделанных модуля, чем 8 сырых. Не начинай новый
    модуль, пока предыдущий не прошёл проверку «читается на телефоне за 12 минут и понятен».
12. Секреты: `.env` не в гите. Если ключ попал в историю — доложи, сам не ротируй.

## СТЕК (менять только с записью причины в TODO.md)
Next.js 15 App Router + TypeScript strict · Tailwind + shadcn/ui (минимально) ·
контент в **MDX** · интерактивы — **чистый Canvas/SVG + React**, без тяжёлых чарт-библиотек ·
прогресс — localStorage/IndexedDB (без бэкенда) · PWA (next-pwa или ручной service worker) ·
Pyodide — ленивая загрузка только на уроках с кодом · Vitest + Playwright · деплой Vercel.
**Бэкенда и базы данных в MVP НЕТ** — это осознанное решение, оно убирает целый класс проблем.
